概要

ゲームの骨格

マス目の上で数字タイルを動かし、ぶつけて計算し、出口から出し切るソロパズル。 盤上にあるのは数字タイルだけで、演算子はタイルの辺に付いている。 どの向きから当てるかで使う演算子と計算の左右が決まるため、算数ではなく 「空間と順序」が難しさの中心になる。

特殊効果（滑る・回す・入れ替える・√・!）は床（マス）の性質として持たせる。 タイルの素性ではないので、合体しても効果が消えるといった例外が発生しない。 全レベルに最短手数ちょうどの手数制限があり、遠回りすると間に合わない。

ルール

1 手の解決手順

実装で最も間違えやすいのが処理の順序。次の順で確定する。 いずれの理由でも成立しなかった場合、手数は消費しない。

  1. タイルと向きを選ぶ。 固定タイルは動かせない（ぶつけられる側にはなれる）。 操作は「タイルを選択 → 同じ行・列のマスをタップ」。
  2. 1 マスずつ進める。 次のマスが盤外・壁なら停止（衝突なし）。次のマスにタイルがあれば停止（衝突あり）。 進入したマスが氷なら、同じ向きに進み続ける。
  3. タイルに阻まれて止まった場合は衝突判定。 接触する 2 辺のうちちょうど片方だけに演算子があるときのみ成立。 両方にある／どちらにも無い場合はぶつかれない（壁と同じ扱い）。
  4. 計算する。 ぶつけた側 演算子 ぶつけられた側 の順。 成立しない結果ならその衝突ごと無効：
    • 割り切れない割り算・0 での割り算
    • 引いて負になる向き（マイナスは扱わない）
    • 結果が 100000 を超える
  5. 合体の後始末。 ぶつけた側は消える。ぶつけられた側は位置と固定フラグを保ち、値が計算結果になる。 辺はぶつけられた側の、使わなかった辺だけが残る。
  6. 衝突せずに動いた場合は、止まったマスの床効果を適用。 適用できない値なら（√ に平方数以外など）そのマスには入れず、手ごと却下。 残り回数が設定された床は 1 消費し、0 になった床はただの床になる。
  7. 成立したら手数を 1 消費。 移動・衝突・出口はいずれも 1 手。

ルール

衝突と辺

マイナスは扱わない。 同じ演算子でも当てる向きで A−B と B−A を選べるため、 符号は常にプレイヤーが選択できてしまう。よって引いて負になる向きは衝突自体を不成立とし、 「大きい方から当てる」という制約として機能させる。0 は許容する。

ルール

床・出口・勝敗

床（マスの性質）

種類表示効果回数
ice≈ そのマスでは止まらず、同じ向きに進み続ける無制限
rotate↻ 辺を時計回りに 90 度回す
(上,右,下,左) → (左,上,右,下)		uses で指定
swap⇄ 全ての辺の + ↔ −、× ↔ ÷ を入れ替えるuses で指定
sqrt√ 値を平方根にする。平方数でないとそのマスに入れないuses で指定
fact! 値を階乗にする。0〜8 でないと入れないuses で指定

uses 未指定なら無制限。0 になった床は効果を失い、ただの床として通過できる。 残り回数は右下に小さく表示し、使い切ったマスは薄く描く。

出口

  • 盤の縁のマスに、外向きの方向を持って置く（up なら row=0、right なら col=cols-1）。マーカーは盤の外側に描く。
  • value で単一値、または minValue／maxValue で範囲を指定。どちらも無ければ任意の値を通す。
  • そのマスに乗っているタイルの値が条件に合うときだけ、タップで盤外へ出せる（1 手）。

勝敗と手数

  • クリア：盤上のタイルが全て無くなる。
  • 失敗：手数制限を使い切った時点でタイルが残っている。「1手戻す」「やり直す」を提示する。
  • 手数制限：全レベルで最短手数ちょうど。余裕は無い。
  • Undo：1 手ごとに（タイル配置・値・辺・固定フラグ・床の残り回数・手数）のスナップショットを積む。
  • クリア判定は失敗判定より優先する（最後の 1 手で出し切った場合はクリア）。

データ

レベルデータ形式

アプリはこの JSON を読むだけでよい。par と limit は 検証ツールが総当たり探索で算出して埋めるので、アプリ側で計算する必要はない。 

{
  "levelId": "v3_004",
  "title": "硬い面どうし",
  "hint": "両方に演算子があると当たらない",
  "tutorial": false,          // 任意。難易度の足切りを免除する印
  "size": 4,                  // 正方形のとき。N×M なら rows / cols を使う
  "rows": 4, "cols": 5,       // 任意。size より優先

  "tiles": [
    { "id": "a", "row": 3, "col": 1, "value": 6,
      "edges": { "right": "×" },   // up / right / down / left から任意に
      "fixed": false }             // 任意。true なら自分から動けない
  ],
  "walls":  [ { "row": 1, "col": 1 } ],
  "floors": [ { "row": 3, "col": 0, "type": "rotate", "uses": 1 } ],
  "exits":  [ { "row": 0, "col": 3, "direction": "up", "value": 26 } ],
  //         範囲出口なら "minValue": 20, "maxValue": 25

  "par": 12,                  // 検証ツールが算出
  "limit": 12                 // 手数制限（= par）
}

演算子は + −（U+2212） × ÷ の 4 種のみ。 ハイフンではなく全角マイナス記号を使っている点に注意。

品質

レベル検証の要件

出題する全レベルは、総当たり探索による以下のチェックを通すこと。 python tools/v3_levels.py が検証と JSON 出力を行う。

項目条件理由
クリア可能解が存在する—
手数制限limit ≥ par。既定は limit = parpar 以下で必ずクリアできることを保証
解法最短手数での解法がちょうど 1 通り別解があると意図した気付きが迂回される
床の必要性床を 1 枚ずつ外すと、制限内で解けなくなる飾りの床を置かない
出口盤の縁にあり、壁の上でないマーカーが盤内に埋まらない
盤サイズ使われない行・列が無い無駄に広い盤を作らない
単調解1 方向だけの移動では解けない「右に動かすだけ」を防ぐ
長さ※par ≥ 8短いと総当たりで解けてしまう
一本道率※≤ 0.45選択の余地がない局面ばかりだと作業になる
迷いどころ※1 局面あたりの外れ手 ≥ 2.0考える必要を担保する
ひっかけ※作れるが出せない値が 2 種以上正解以外の道筋を用意する

※ は "tutorial": true のレベルでは免除。

画面

UI 仕様

デザイントークン

用途色適用先

floor#EDE3D2回転・入替・√・! の床

数字・演算子は等幅フォント、UI ラベルはシステムのゴシック体。

画面①：レベル選択

  • グリッド表示。各カードに レベル番号／タイトル／N手以内／クリア済みなら ✓ と best 手数。
  • 順序制限は設けない（全レベル最初から選べる）。

画面②：パズル

  • 上部に 残り手数 N / M手以内、「戻す」「リセット」。残り 2 手以下で赤く表示。
  • ヒント文を 1 行表示。
  • タイルはマス内に収め、辺の演算子はタイルの外周に小さなタブとして描く。
  • 出口は盤の外側に丸いマーカー（矢印＋値）。出せる状態のときは脈動させる。
  • 操作：タイルをタップで選択 → 同じ行・列のマスをタップでその向きへ。
  • 成立しない操作は、理由を短文で表示する（例：「両方に演算子があるのでぶつかれません」「引くとマイナスになるので当てられません」「平方数でないと √ のマスに入れません」）。
  • クリア時：手数と制限を表示し「レベル選択」「次へ」。失敗時：「1手戻す」「やり直す」。

保存

shared_preferences に、レベルごとの { cleared: bool, bestMoves: int } のみ保存する。 保存に失敗してもゲーム進行は継続すること（ストレージ不可の環境がある）。

引き継ぎ

本番実装への移行

移植するもの / しないもの

  • 移植する：コアルール（本書 2〜3 章）と、検証済みレベル JSON。
  • 移植しない：POC の HTML/JS そのもの、Python のソルバー。ソルバーはレベル製作用のツールとして手元に残す。

推奨する構成

assets/levels/levels_v3.json     検証済みレベル（ツールが生成）
lib/game/rules.dart              純粋関数：applyOp / collide / rotate / swap / slide / land
lib/game/level.dart              データモデル（Level / TileData / FloorData / ExitData）
lib/game/game_state.dart         盤面状態・手数・Undo スタック
lib/screens/level_select.dart    画面①
lib/screens/puzzle.dart          画面②
test/rules_test.dart             ルールの単体テスト
test/solutions_test.dart         最短手順の再生テスト

移植の正しさは、最短手順の再生で検証できる。 tools/solutions_v3.json に全レベルの最短手順が操作列として入っている。 これを Dart 側で再生し、全レベルが制限手数ちょうどでクリアになることを確認すれば、 ルールの移植ミスはまず検出できる。POC でも同じテストを通してある。

レベルを追加するときの手順

  1. tools/v3_levels.py の LEVELS に候補を書く
  2. python tools/v3_levels.py --report で検証（不合格なら理由が出る）
  3. 合格したら python tools/v3_levels.py で JSON と最短手順を出力
  4. アプリの assets に反映し、再生テストを回す

範囲

スコープ外

  • 通信・サーバー・アカウント（完全オフラインで動作すること）
  • UGC・チャット・ランキング共有
  • レベルの自動生成（ツールに実験用の生成器はあるが、出題は手作り＋検証で行う）
  • タイマー・ヒント機能・広告・課金
  • 押し（ブロックを押しのける仕様）… 検討したが、難易度指標が変わらず不可逆性を弱めるため不採用
  • マイナス値・絶対値・符号反転 … 当てる向きで符号を選べるため意味を持たず不採用
