## ワープの床

指定した数字のタイルだけが通れる関門。出口とは違い、盤上の別の場所へ移す。

ねらい:

- **特定の数を作らせる**。「この手数で解くには、まずワープを通れる数を
  用意しなければならない」という制約が生まれる。値を指定しない出口
  （範囲出口）とは逆に、ここは「ぴったり合わせる」ことを強制できる。
- **盤を分割して行き来させる**。壁で完全に仕切ると実質2つのパズルを
  並べただけになってしまうが（そう指摘を受けて作り直した経緯がある）、
  ワープで繋げば「片方で作った数をもう片方へ運ぶ」形にできる。
  分割の弊害を避けつつ、盤を広く使える。
- **数字を指定しないワープ**も可。こちらは移動の自由度を上げる装置になり、
  選択肢が増える方向に働く。

決めること:

- 対になる出口をどう表すか（座標の組か、id で結ぶか）
- 一方通行か双方向か
- 使用回数の制限を設けるか（他の床と同じく uses で扱えるはず）
- ワープ先が埋まっているときの扱い（入れない / 押し出す / すり抜ける）
- 氷との組み合わせ（滑ってワープに入ったらどう出るか）

検証側で追加が要るもの:

- solver の遷移にワープを足す
- 「ワープが無くても解ける」＝飾りになっていないかの判定
  （floor_necessity と同じ考え方）
